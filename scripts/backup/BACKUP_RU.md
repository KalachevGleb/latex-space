# Резервное копирование LaTeXSpace — инструкция для человека без сисадминских навыков

Всё делает один файл: `overleaf-backup.sh`. Он лежит в каталоге установки
(там же, где `docker-compose.yml`), в подкаталоге `scripts/`. Никаких переменных
окружения — все настройки в самом начале файла, и по умолчанию их менять не нужно.

Ниже везде подразумевается, что вы зашли на сервер по ssh и находитесь в каталоге
установки (например `cd /opt/overleaf`).

## Первый раз: включить автоматические бэкапы

```bash
sudo apt install borgbackup        # один раз; у вас borg, вероятно, уже стоит
./scripts/overleaf-backup.sh install
```

После этого:
* каждую ночь в 03:30 делается копия (сервис не останавливается);
* каждое воскресенье в 05:00 последняя копия **проверяется по-настоящему**:
  архив распаковывается, база разворачивается во временный MongoDB и считаются
  пользователи/проекты;
* старые копии удаляются сами (хранятся 14 ежедневных, 8 недельных, 12 месячных);
* копии лежат в `backups/` внутри каталога установки.

## Перед обновлением LaTeXSpace

```bash
./scripts/overleaf-backup.sh backup --stop
```

Сервис остановится на 1–3 минуты, будет снята полная копия (включая «сырые»
файлы базы), сервис запустится обратно. Дождитесь строки `Бэкап готов: ...` —
запомните имя. Теперь обновляйтесь. Если что-то пошло не так:

```bash
./scripts/overleaf-backup.sh restore overleaf-2026-08-25_03-30-00-stop
```

## Проверить, что всё в порядке (раз в неделю-две, 5 секунд)

```bash
./scripts/overleaf-backup.sh status
```

Зелёное `OK` и «N ч. назад» меньше суток — всё хорошо (и отдельной строкой —
состояние копии в облаке). Если красное или предупреждение — смотрите
`backups/backup.log`.

## Все команды

| Команда | Что делает |
|---|---|
| `install` | настроить cron и сделать первый бэкап |
| `backup` | копия без остановки сервиса |
| `backup --stop` | копия с остановкой (перед обновлением) |
| `list` | список копий |
| `status` | когда был последний бэкап и удался ли |
| `verify` | глубокая проверка последней копии (то, что cron делает по воскресеньям) |
| `restore ИМЯ` | восстановить копию. Спросит подтверждение. Текущие данные не удаляются, а переименовываются в `*.before-restore-…` |
| `cloud-setup` | настроить отправку копий в облако (Яндекс.Диск / Google Диск / S3) |
| `cloud-status` | что сейчас лежит в облаке и когда отправлялось |
| `cloud-pull` | скачать копии из облака обратно на сервер |

## Копия за пределами сервера (важно)

Бэкап на том же сервере спасает от «случайно удалил проект» или неудачного
обновления, но не спасёт, если сервер целиком пропадёт (сломался, заблокировали,
кончилась оплата). Поэтому копию нужно держать ещё где-то. Вариантов ровно три,
и они не исключают друг друга.

### 1. Копия в облако — Яндекс.Диск, Google Диск или S3 хостинга (рекомендую)

Одна команда, дальше само:

```bash
sudo apt install rclone
./scripts/overleaf-backup.sh cloud-setup
```

Скрипт запустит настройку подключения и подскажет, что нажимать. Для Яндекс.Диска
или Google Диска нужен только их обычный аккаунт (тот же, что для личных файлов);
на сервере без браузера rclone даст ссылку — открываете её на своём компьютере,
разрешаете доступ, вставляете код обратно в терминал. После этого каждая ночная
копия автоматически уходит в облако.

Сколько места нужно: примерно столько же, сколько занимают ваши данные (borg
сжимает и хранит только изменения, поэтому 14 ежедневных копий занимают лишь
немногим больше одной). Бесплатных 10–15 ГБ Яндекс.Диска/Google Диска обычно
хватает надолго; посмотреть текущий объём — `./scripts/overleaf-backup.sh cloud-status`.

Если в панели вашего хостинга есть «объектное хранилище» / «S3» — это тот же
вариант, только надёжнее и платно (обычно 1–2 рубля за ГБ в месяц). При настройке
выберите тип `s3`, ключи возьмите в панели хостинга.

Проверить, что копии уходят: `./scripts/overleaf-backup.sh cloud-status`.
Скачать копии из облака обратно (если сервер пришлось переустановить):
`./scripts/overleaf-backup.sh cloud-pull`, дальше обычный `restore`.

### 2. Снимки (снапшоты) у хостинга — самое простое, если такое есть

Почти у всех хостингов в панели управления есть «Снапшоты», «Бэкапы» или
«Резервные копии» для сервера целиком — это отдельная платная галочка
(обычно 20–30% от стоимости сервера). Включить стоит: снимок сохраняет весь
сервер, и восстановление — это одна кнопка в панели, без всяких команд.

Важно: снапшоты хостинга — это **дополнение**, а не замена. Они делаются с
работающей базы данных без сброса буферов, поэтому годятся для «поднять сервер
целиком после аварии», но хуже для «вернуть один вчерашний проект». Наш скрипт
закрывает второе. Вместе они дают хорошее покрытие.

Дополнительный диск, который «покупается отдельно и масштабируется» — это,
скорее всего, обычный диск того же сервера. Держать бэкапы на нём немного лучше,
чем на системном (защищает от переполнения и от ошибки при обновлении), но
от потери самого сервера не спасает. Если такой диск примонтирован, впишите путь
к нему в строку `BACKUP_DIR_2=""` в начале скрипта.

### 3. Скачивать копии к себе на компьютер

Раз в месяц вручную:

```bash
scp -r ПОЛЬЗОВАТЕЛЬ@СЕРВЕР:/opt/overleaf/backups/borg ~/overleaf-backup-копия
```

Медленно и требует помнить об этом, но одна такая копия «на своём ноутбуке» —
уже сильно лучше, чем ничего.

## И ещё

* **Раз в несколько месяцев** запускайте `verify` вручную и смотрите, что оно
  говорит «Копия исправна» с разумным числом пользователей и проектов.
* Если у вас уже настроен borg для чего-то другого — просто добавьте в тот бэкап
  каталог `backups/` целиком, он заберёт его как обычные файлы.

## Что лежит в копии

* MongoDB — пользователи, проекты, тексты, комментарии, права (дамп `mongodump`,
  а в режиме `--stop` ещё и сырые файлы базы);
* `sharelatex_data` — загруженные файлы и история версий (без кэша компиляции,
  он пересоздаётся сам);
* Redis — сессии пользователей;
* `docker-compose.yml`, `.env`, `VERSION`.

Перед горячим бэкапом скрипт принудительно сбрасывает несохранённые правки
последних минут из памяти в базу, поэтому «на горячую» тоже ничего не теряется.
