## 🛡️ Уровни защиты (кратко)

```
🔒 Docker изоляция          ✅ Каждая компиляция в отдельном контейнере
🔒 ReadonlyRootfs           ✅ Вся FS read-only
🔒 Network Disabled         ✅ Нет доступа к сети
🔒 CapDrop: ALL             ✅ Нет capabilities
🔒 Seccomp profile          ✅ Whitelist системных вызовов
🔒 no-new-privileges        ✅ Защита от privilege escalation
🔒 Tmpfs security           ✅ noexec, nosuid, nodev
🔒 TeX restrictions         ✅ openout_any=r, shell_escape=f
```

## ❓ FAQ

### Влияет ли это на производительность?
**Нет.** Влияние минимальное (<1%). Tmpfs даже быстрее обычной FS.

### Будут ли работать мои LaTeX документы?
**Да.** Обычные документы работают без изменений. Исключение: пакеты, требующие shell-escape (например, `minted`).

### Можно ли отключить защиту?
**Да,** но не рекомендуется. См. документацию в `SECURITY_SANDBOXED_COMPILATION_RU.md`.

### Как проверить, что защита работает?
Используйте `SECURITY_TEST_DOCUMENT.tex` или команды из раздела "Что делать дальше" выше.

## 🐛 Проблемы?

### Компиляция не работает?
```bash
# Проверьте логи
docker compose -f develop/docker-compose.yml logs clsi

# Проверьте статус контейнеров
docker ps -a --filter "name=project-"
```

### Permission denied?
Проверьте, что tmpfs правильно настроены:
```bash
docker inspect <container_id> | jq '.[0].HostConfig.Tmpfs'
```

### Нужен shell-escape?
См. раздел "Разрешение shell-escape" в `SECURITY_SANDBOXED_COMPILATION_RU.md`.
