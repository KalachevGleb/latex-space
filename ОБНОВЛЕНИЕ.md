# Как обновить LaTeXSpace на сервере

Сервер: `latexspace.intsysmagazine.ru`, установка в `~/latexspace` у пользователя `glebk`.
Всё делается от обычного пользователя, **sudo не нужен**.

Обновление состоит из двух независимых пакетов:

| Пакет | Что внутри | Размер | Когда нужен |
|---|---|---|---|
| `overleaf-fix.tar.gz` | образ приложения (Docker) | ~560 МБ, заливается ~1.5 ч | изменился код Overleaf |
| `overleaf-scripts.tar.gz` | `install_fix.sh`, `overleaf-backup.sh`, инструкция | ~50 КБ, секунды | изменились только служебные скрипты |

## 1. На Mac — собрать

```bash
cd /Users/gleb/Projects/overleaf
git add -A && git commit -m "описание изменений"   # чтобы версия в пакете соответствовала коду
./scripts/prepare_fix.sh          # оба пакета; если код приложения не менялся — образ переиспользуется, Docker не запускается
./scripts/prepare_scripts.sh      # только маленький пакет скриптов (секунды)
```

`prepare_fix.sh` сам понимает, менялся ли код приложения (`services/`, `libraries/`,
`package.json`) с одной из уже собранных ревизий; если нет — берёт готовый образ.
Пересборка (10–15 минут) происходит только когда код действительно менялся.

Если сборка упала с `npm error network` — это обрыв связи при скачивании пакетов,
просто запустите команду ещё раз (скачанное кэшируется).

## 2. Скопировать на сервер

`rsync` вместо `scp`: при обрыве связи докачивает с места остановки, а не с нуля.

```bash
# только скрипты (быстро)
rsync -avz --progress overleaf-scripts.tar.gz install_fix.sh glebk@latexspace.intsysmagazine.ru:~/

# скрипты + образ (долго)
rsync -avz --progress overleaf-fix.tar.gz overleaf-scripts.tar.gz install_fix.sh glebk@latexspace.intsysmagazine.ru:~/
```

## 3. На сервере — обновить

```bash
ssh glebk@latexspace.intsysmagazine.ru
bash ~/install_fix.sh ~/overleaf-scripts.tar.gz                        # только скрипты: сервис не трогается
bash ~/install_fix.sh ~/overleaf-scripts.tar.gz ~/overleaf-fix.tar.gz  # скрипты + образ
bash ~/install_fix.sh ~/overleaf-fix.tar.gz                            # только образ
```

Пакет образа можно не заливать повторно: если на сервере уже лежит
`~/overleaf-fix.tar.gz` с нужной версией, просто укажите его снова.

При обновлении образа скрипт сам:
1. делает резервную копию (`~/latexspace/backups/`) — если копия не удалась, обновление отменяется, **сервис при этом остаётся выключенным** — запустите: `cd ~/latexspace && docker compose up -d`;
2. запоминает текущую версию для отката;
3. загружает новый образ, запускает сервис и ждёт, пока он ответит;
4. пишет `Готово. Работает версия: …`.

Конфигурация (`.env`, `docker-compose.yml`, `overleaf_config.json`) и данные не трогаются.

## 4. Проверить

Открыть сайт, войти, открыть проект, скомпилировать. Установленную версию видно
по адресу https://latexspace.intsysmagazine.ru/version.json (поле `commitShort`)
или командой на сервере:

```bash
docker inspect --format '{{index .Config.Labels "com.overleaf.ce.revision"}}' overleaf-custom:latest
```

## Если что-то сломалось — откат

```bash
bash ~/install_fix.sh --rollback
```

Возвращает предыдущий образ и запускает сервис. Данные при обновлении не менялись,
поэтому откат безопасен. Если нужно вернуть и данные (крайний случай):
`~/latexspace/scripts/overleaf-backup.sh list` → `restore ИМЯ`.

## Что ещё полезно знать

* Логи: `cd ~/latexspace && docker compose logs -f sharelatex`
* Состояние бэкапов: `~/latexspace/scripts/overleaf-backup.sh status`
* Регулярные бэкапы (один раз): `~/latexspace/scripts/overleaf-backup.sh install`
* Копия в облако (один раз): `~/latexspace/scripts/overleaf-backup.sh cloud-setup`
* Старые образы `install_fix.sh` удаляет сам, оставляя текущий и предыдущий.
* Файл `~/latexspace/VERSION` обновляется автоматически, по нему видно, что установлено.
* Полная переустановка через `install_overleaf.sh` нужна только при смене версии
  Node/ОС в `server-ce/Dockerfile-base` — см. предупреждение про конфиг в
  [README.deployment.md](README.deployment.md).
