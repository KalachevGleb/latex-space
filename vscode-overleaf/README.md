# LatexSpace — расширение VSCode/Cursor

Локальная работа с проектами LatexSpace (кастомный сервер на базе Overleaf CE;
к облачному overleaf.com плагин не подключается — API несовместимы):

- **Реальное время**: открытые .tex-документы синхронизируются по мере
  набора через тот же OT-протокол (websocket), что и браузер. Понятия
  «сохранить, чтобы отправить» нет: правки уходят сразу, чужие правки
  появляются в буфере сразу, конкурентное редактирование сливается на
  уровне операций — как между двумя вкладками браузера. Индикатор в
  статус-баре: «⟟ LatexSpace: live».
- **Боковая панель** (значок LatexSpace): вход и выход из учётной записи
  (кнопка выхода — в заголовке панели «Проекты»; после выхода можно войти
  под другой учётной записью), список проектов (название, дата изменения,
  роль — без внутренних ID), действия текущего проекта.
- **Комментарии как в веб-версии**: позиции ведутся той же библиотекой
  `ranges-tracker`, что и на сервере, поэтому подсветка и переход к строке
  точные и мгновенные; новые комментарии из веба появляются сразу
  (socket-события). Добавление — как в Overleaf: выделите текст (или
  наведите на «+» у номера строки) → введите комментарий прямо в
  редакторе, Esc — отмена. Существующие комментарии видны инлайн-виджетами
  у своих фрагментов: ответы и «решено» — там же. Дублируется в панели
  LatexSpace и контекстном меню.
- **Track changes (рецензирование)**: постоянный индикатор режима в
  статус-баре — «✎ Редактирование» / «Рецензирование» (при включённом
  рецензировании кнопка «зажата» — с цветной подложкой); переключение —
  кликом по индикатору или значком в панели «Правки». Ваши правки уходят
  с меткой рецензирования (`meta.tc`, тот же протокол, что в браузере),
  чужие tracked-правки подсвечиваются в редакторе (вставки — зелёным,
  удаления — красным маркером с зачёркнутым текстом), список правок по
  файлам с **принятием и отклонением** по кнопкам (reject — как в вебе:
  обратная операция с u-флагом через OT). Пара «вставка + удаление сразу
  за ней» отображается **одной правкой-«заменой»** («было → стало»), как
  в вебе, и принимается/отклоняется целиком. Замена выделения (вставка
  поверх) даёт пословный diff со слиянием близких изменений, а не
  «всё удалить + всё вставить».
- **Файловая синхронизация** — для бинарных файлов, закрытых документов
  и как fallback при обрыве соединения: трёхсторонняя сверка
  «локальный файл ↔ базовая копия ↔ сервер», расхождения никогда не
  перезаписываются молча, а показываются как конфликты.
- **Новые файлы не отправляются автоматически** (как untracked в git):
  файлы, появившиеся в папке (их часто плодят другие расширения при
  автокомпиляции), попадают в список «новых» — плагин показывает одно
  сгруппированное уведомление, отправка только явная (выбор галочками
  через уведомление или меню синхронизации). Вернуть авто-отправку:
  `latexspace.sync.autoPushNewFiles: true`.
- **Ctrl/Cmd+S в .tex = компиляция** (`latexspace.compile.onSave`,
  по умолчанию включено): в live-режиме «сохранить» само по себе не
  нужно — правки синхронизируются по мере набора.
- **Детект конфликтующих расширений**: при открытии проекта плагин
  сканирует настройки установленных расширений (LaTeX Workshop,
  mathematic.vscode-latex и др.) на включённые автокомпиляцию/автодействия
  при сохранении и предлагает отключить ТОЛЬКО эти функции (настройка
  рабочей области) — подсветка синтаксиса, сниппеты и прочее сохраняются.
  Подсветку LaTeX эти расширения дают хорошую, удалять их не нужно.
- **Кнопка «▶ Компилировать»** в статус-баре и на панели редактора
  (`Cmd/Ctrl+Alt+B`). Главный смысл плагина — **разгрузка сервера**:
  по умолчанию (`compile.mode: auto`) компиляция идёт **локально**
  через latexmk из TeX Live, сервер в компиляции не участвует вообще;
  если TeX Live не установлен — автоматический fallback на серверную
  компиляцию (с одноразовой подсказкой). Принудительно: `local` /
  `server`.
- **PDF в закреплённой вкладке** рядом с кодом, автообновление после
  компиляции.
- **SyncTeX в обе стороны**: `Ctrl/Cmd+Click` в PDF → переход к исходнику;
  `Ctrl/Cmd+Click` (или `Cmd/Ctrl+Alt+J`) в .tex → подсветка места в PDF.
- **Сборка в `.build/`** — исходники не замусориваются; артефакты,
  случайно попавшие в корень, автоматически убираются.
- **Ошибки LaTeX** из лога — в панели «Problems».

Подсветка синтаксиса LaTeX — штатная VSCode. Если установлен LaTeX Workshop,
отключите его автосборку (`latex-workshop.latex.autoBuild.run: "never"`),
иначе он будет собирать проект в корень параллельно с плагином.

## Установка

Пользователям: страница **`/vscode-plugin`** на сервере LatexSpace —
кнопка скачивания .vsix и инструкция (ссылка есть в боковой панели
списка проектов и в меню аккаунта). Файл раздаётся статически из
`services/web/public/vscode/latexspace.vsix`.

Сборка из исходников:

```bash
cd vscode-overleaf
npm install
npm run package          # соберёт latexspace-<версия>.vsix
npm run deploy:web       # + положит его в services/web/public/vscode/
```

VSCode/Cursor: `Extensions → … → Install from VSIX…` или
`code --install-extension latexspace.vsix` /
`cursor --install-extension latexspace.vsix`.

### Deep links (после установки)

Расширение регистрирует URI-обработчик:

- `vscode://peer-review.latexspace/open?server=<url>` — вход (адрес
  сервера подставится) и выбор проекта; кнопки «Открыть в VS Code /
  Cursor» на странице `/vscode-plugin` используют именно это.
- `vscode://peer-review.latexspace/open?server=<url>&projectId=<id>&name=<имя>` —
  открыть конкретный проект (задел для кнопки «Открыть в VSCode» у
  проекта в веб-интерфейсе).

Для Cursor схема `cursor://` вместо `vscode://`. Ссылки работают только
при установленном расширении: «в один клик установить по ссылке» умеет
только VS Code Marketplace (`vscode:extension/<id>`), куда расширение
пока не публикуется.

## Начало работы

1. В боковой панели LatexSpace нажмите **«Войти»** — три поля: адрес
   сервера, e-mail, пароль (та же учётная запись, что в браузере; пароль
   хранится в Keychain). После входа кнопка исчезает и появляется список
   проектов.
2. Кликните проект — плагин скачает его в выбранную папку и откроет;
   главный .tex-файл откроется автоматически. Папка запоминается: следующий
   клик по проекту сразу открывает её.
3. Дальше — обычная работа: сохранение отправляет файл на сервер, изменения
   с сервера подтягиваются фоном (15 с), компиляция — по кнопке.

Папку проекта можно открывать и напрямую (`File → Open Folder`) — плагин
распознает привязку сам (`.latexspace/project.json`; старые привязки
`.overleaf/` мигрируются автоматически).

## Защита от рассинхронизации

- Базовая копия последней синхронизации хранится в `.latexspace/base/`.
- **При открытии папки** выполняется сверка. Если есть локальные изменения,
  не отправленные на сервер, плагин покажет диалог:
  - **Синхронизировать** — локальные правки отправятся; если сервер тоже
    менялся, расхождения станут конфликтами (ничего не перезаписывается);
  - **Показать изменения** — diff «синхронизировано ↔ локально» встроенным
    сравнением VSCode;
  - **Оффлайн-режим** — синхронизация полностью отключается (доступна
    локальная компиляция); вернуться: «LatexSpace: Выйти из оффлайн-режима».
- В процессе работы конфликт по файлу разрешается через статус-бар:
  diff / взять серверную / оставить локальную.
- Удалённое при синхронизации сохраняется в `.latexspace/trash/`.
- Удаление файлов на сервере — только явной командой
  «Полная отправка на сервер» с подтверждением.

Рекомендация: не редактируйте один файл одновременно в браузере и локально —
конфликт будет обнаружен, но сливать его придётся вручную.

## SyncTeX

Работает после первой компиляции; режим следует за фактическим режимом
последней компиляции: локальная — утилита `synctex` из TeX Live,
серверная — SyncTeX API сервера.

### Точный SyncTeX (по умолчанию включён при локальной компиляции)

SyncTeX работает построчно, поэтому в длинных абзацах синхронизация
грубая — весь абзац маппится в одну строку исходника. Плагин решает это
«развёртыванием»: компиляция идёт по теневой копии
(`.latexspace/exploded/`), где в безопасных местах пробелы между словами
заменены переносами строк (для TeX одиночный перенос эквивалентен
пробелу) — каждая строка мала, и синхронизация работает с точностью до
слова. Проверено реальной сборкой: текст PDF идентичен байт в байт, а
обратный SyncTeX вместо «весь абзац → строка 8» даёт отдельную строку
на каждое слово.

- Разбор — настоящий конечный автомат, не regexp: вложенность `{}`,
  стек `\begin/\end`, `$…$`/`\(…\)`/`\[…\]`, комментарии, экранирование
  (`\%`, `\{`, `\ `), `\verb<делим>`, verbatim-окружения (сканируются как
  сырой текст). Пустые строки (= `\par`) никогда не создаются.
- Дробление — только в глобальной области, преамбуле и окружениях из
  белого списка `latexspace.synctex.splitEnvironments` (document, proof,
  itemize, …); equation, tikz, таблицы и всё незнакомое не трогаются.
- Позиции ошибок из лога и SyncTeX в обе стороны пересчитываются через
  двусторонний маппинг (оригиналы файлов не изменяются).
- Отключение: `latexspace.synctex.fineGrained: false`.

**План — перенос на сервер**: тот же алгоритм (`src/latex/explode.ts`,
чистый модуль без зависимостей от VSCode) можно применить в CLSI перед
компиляцией + пересчёт в `_syncTeX` веб-сервиса — тогда точная
синхронизация появится и в браузере, и при серверной компиляции плагина. Переход из .tex в PDF повешен
на `Ctrl/Cmd+Click` (через definition-провайдер; сработает, когда открыта
PDF-панель) и на `Cmd/Ctrl+Alt+J` / контекстное меню.

## Правки от ИИ-инструментов

Правки, которые вносит ИИ (Cursor Composer, Copilot, Claude Code и другие
агенты), синхронизируются так же, как правки пользователя — специальной
настройки не требуется. Есть три пути, и все покрыты:

1. **ИИ редактирует открытый документ** (через API редактора — так работают
   Cursor, Copilot, встроенные агенты): изменения буфера попадают в тот же
   OT-поток, что и набор с клавиатуры, и уходят на сервер мгновенно.
   При включённом рецензировании правки ИИ записываются как предлагаемые
   (tracked changes) — их можно принимать/отклонять как правки человека.
2. **ИИ пишет файл на диск, файл открыт в редакторе** (CLI-агенты):
   VSCode перечитывает буфер (если нет несохранённых правок — а плагин
   автосохраняет через 1,5 с), изменение превращается в diff-операцию.
   Для больших замен (агент переписал файл целиком) diff считается
   двухуровнево: построчно, затем изменённые блоки уточняются пословно —
   картина правок остаётся точечной.
3. **ИИ пишет в неоткрытый файл**: срабатывает файловый watcher, файл
   уходит через upload-by-path, а diff по документу вычисляет сервер
   (DiffCodec) и рассылает всем клиентам операциями.

Рекомендация для CLI-агентов: не редактируйте один файл одновременно
агентом с диска и руками в несохранённом буфере — это единственное окно,
где VSCode покажет конфликт «файл изменён извне».

## Служебные файлы журнала

Файлы, которые генерирует издательская система при компиляции
(`_*.in`, `*.abstract.*.tex`, `*.keywords.*.txt`, `*.authors.tsv` и т.п.),
являются частью проекта и синхронизируются, но скрываются из проводника
(`files.exclude`). Список шаблонов: `latexspace.ui.hiddenFilePatterns`.

## Смоук-тест против живого сервера

```bash
npx esbuild scripts/smoke.ts --bundle --platform=node --outfile=out/smoke.js \
  && LATEXSPACE_URL=http://localhost LATEXSPACE_EMAIL=... LATEXSPACE_PASSWORD=... node out/smoke.js
```

Прогоняет реальный клиент по всему циклу: вход → проект → upload-by-path →
zip → версии истории → sync-from-zip → комментарии → компиляция → PDF →
SyncTeX в обе стороны.

## Тесты против живого сервера

```bash
# REST-цикл (вход → проект → sync → компиляция → SyncTeX)
npx esbuild scripts/smoke.ts --bundle --platform=node --outfile=out/smoke.js \
  && LATEXSPACE_PASSWORD=... node out/smoke.js
# Реальное время (два OT-клиента, конкурентные правки, внешние изменения)
npx esbuild scripts/smoke-rt.ts --bundle --platform=node --outfile=out/smoke-rt.js \
  && LATEXSPACE_PASSWORD=... node out/smoke-rt.js
```

## Ограничения (планы)

- Курсоры других участников не отображаются (протокол clientTracking
  есть — можно добавить).
- Переименование файла = удаление + создание.

## План: качество tracked changes при вставках

Наблюдение по поводу «побуквенного diff» на сервере: рассинхрон возможен
только если клиент и сервер считают diff НЕЗАВИСИМО. В текущей архитектуре
это не так: diff в одном месте (DiffCodec на сервере при upsert), результат
рассылается готовыми операциями, а все клиенты (веб, плагин) просто их
применяют. Значит, серверный алгоритм можно свободно улучшать (например,
semantic cleanup из diff-match-patch: посимвольный diff → укрупнение до
границ слов + слияние фрагментов ближе N символов) — клиенты менять не
нужно. Плагин же при live-редактировании вообще не порождает diff:
операции — это буквальные действия пользователя, поэтому картина правок
из плагина естественная по построению.

## Контракт API (что должно оставаться стабильным на сервере)

Расширение, в отличие от браузера, обновляется у пользователей не
синхронно с сервером — эти точки менять только с обратной
совместимостью:

- `GET /dev/csrf` (выдача CSRF-токена; браузер получает токен иначе —
  из meta-тега страницы, так что этим роутом пользуется только плагин
  и тесты) и `POST /login` (JSON, поля `email`/`password`/`_csrf`).
- `POST /api/project` (список проектов), `GET /project/:id/entities`,
  `GET /project/:id/download/zip`.
- `POST /project/:id/upload-by-path` (поля `qqfile`/`name`/`path`) и
  `POST /project/:id/sync-from-zip`.
- `GET /project/:id/version` (лёгкий опрос версии; при 404 плагин
  откатывается на `GET /project/:id/updates` — можно убрать fallback,
  когда все серверы обновятся).
- Компиляция: `POST /project/:id/compile` (в теле `editorId`),
  `sync/code` и `sync/pdf` (query `editorId`+`buildId`+`clsiserverid`).
- Комментарии/правки: `/project/:id/threads`, `/project/:id/ranges`,
  `/api/project/:id/comments`, `thread/:id/messages|resolve|reopen`,
  `doc/:docId/changes/accept`.
- Websocket-протокол socket.io 0.9 целиком: handshake с `?projectId=`,
  `joinDoc` (escape-кодировка строк), `applyOtUpdate` с `meta.tc`,
  события `otUpdateApplied`, `reciveNewDoc`/`reciveNewFile`/… (имена с
  опечаткой — тоже контракт), `accept-changes`, `toggle-track-changes`,
  комментарийные события.
